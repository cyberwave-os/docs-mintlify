The Cyberwave Python SDK (`cyberwave`) lets you control robots, manage digital twins, and stream sensor data with a few lines of Python. This guide takes you from an empty terminal to a moving robot in the free Playground simulation, no hardware required.

<Note>
  Already comfortable with the basics? The [full Python SDK reference](/overview/tools/python-sdk) covers joint control, video streaming, workflows, datasets, AI models, and more.
</Note>

## Prerequisites

- **Python 3.10 or higher** installed on your machine
- A **Cyberwave account** ([request early access](https://cyberwave.com/request-early-access) if you don't have one)
- A **Cyberwave API key** (we'll generate one in Step 2)

## Step 1: Install the SDK

Install the SDK and CLI from PyPI:

```bash
pip install cyberwave cyberwave-cli
```

Verify the install:

```bash
cyberwave --help
```

## Step 2: Get your API key

<Steps>
  <Step title="Open your profile">
    Go to your [Cyberwave profile](https://cyberwave.com/profile) and open **Profile → Access**.
  </Step>
  <Step title="Create a new key">
    Create a user token, give it a name (e.g. "Quickstart"), choose the workspaces it can act in, and copy the key. You won't be able to see it again, so store it somewhere safe. See [API tokens](/feature-reference/api-tokens) for scopes and service tokens.
  </Step>
</Steps>

## Step 3: Authenticate

The SDK reads your API key from the `CYBERWAVE_API_KEY` environment variable. This is the recommended approach — it keeps secrets out of your code.

```bash
export CYBERWAVE_API_KEY="your_api_key_here"
```

If your token is scoped to more than one workspace, also tell the SDK which one to use. Otherwise requests fail with `400 workspace_required`:

```bash
export CYBERWAVE_WORKSPACE_ID="your_workspace_uuid"   # or Cyberwave(workspace_id=...)
```

Then initialize the client with no arguments:

```python
from cyberwave import Cyberwave

cw = Cyberwave()  # picks up CYBERWAVE_API_KEY automatically
```

<Tip>
  Prefer to pass the key explicitly? Use `Cyberwave(api_key="your_api_key_here")`. Avoid this in code you commit or share.
</Tip>

## Step 4: Control your first robot

The snippet below creates a digital twin of an [SO-101 robot arm](https://cyberwave.com/catalog), runs it in the free **Playground** simulation, and moves one of its joints. Nothing here touches physical hardware, so it's safe to run as-is.

```python
import time
from cyberwave import Cyberwave

# 1. Connect (reads CYBERWAVE_API_KEY from your environment)
cw = Cyberwave()

# 2. Create (or fetch) a digital twin from the asset catalog
robot = cw.twin("the-robot-studio/so101")

# 3. Run against the free Playground simulation, not a physical robot
cw.affect("playground")

# 4. Take control of the twin before the first command
robot.policy.ensure_attached()
time.sleep(2)

# 5. Move a joint — 45 degrees on the shoulder
robot.joints.set("shoulder_pan", 45, degrees=True)

# 6. Read it back (positions are in radians)
print("Joints:", robot.joints.list())
print("States:", robot.joints.get())
```

<Note>
  `cw.affect("simulation")` is different: it starts a MuJoCo physics simulation, a billable cloud instance that uses [credits](/billing/credits) (about 0.6 credits per hour). Use it when you need physics or rendered camera frames. `"playground"` is free.
</Note>

Run it:

```bash
python quickstart.py
```

You should see output like this (UUIDs, URLs and joint lists will differ):

```text
[Cyberwave] No environment specified — created a new 'Quickstart Environment'.
  View it at: https://cyberwave.com/...
  Tip: set environment_id= (or CYBERWAVE_ENVIRONMENT_ID) to skip this step.
Twin <uuid>: controller policy was just attached. This command may have been lost while the robot was still setting up; retry in a few seconds.
Joints: ['shoulder_pan', ...]
States: JointStateView({'shoulder_pan': 0.785..., ...})
```

The "may have been lost" warning appears only on the first run, when the controller is attached. The `time.sleep(2)` covers it.

<Check>
  If you see the joint names and their positions, it worked. `joints.get()` returns a live dict that keeps updating. Open the link the SDK printed to watch the arm move in the 3D viewport.
</Check>

## What just happened

<AccordionGroup>
  <Accordion title="cw = Cyberwave()">
    Creates the SDK client and authenticates using your API key. It establishes connections to both the REST API (for twins, catalog, workflows) and the MQTT API (for real-time control).
  </Accordion>
  <Accordion title='cw.twin("the-robot-studio/so101")'>
    Resolves the `vendor/model` asset from the catalog and returns a twin. If you don't have an environment yet, the SDK auto-creates a "Quickstart Environment", places the twin there, and prints its URL. Create the twin before calling `cw.affect(...)`, so the client knows which environment to use.
  </Accordion>
  <Accordion title='cw.affect("playground")'>
    Tells the SDK that your commands should drive the **digital twin in the Playground**, a free kinematic simulation, rather than a physical robot. Switch to `cw.affect("live")` later to run the exact same code against real hardware.
  </Accordion>
  <Accordion title="robot.policy.ensure_attached()">
    Exactly one controller drives a twin at a time. This attaches a teleop controller policy so the SDK can send joint commands. The first command would do it anyway, but that command can be lost while the controller starts, so attach first and wait a moment.
  </Accordion>
  <Accordion title='robot.joints.set("shoulder_pan", 45, degrees=True)'>
    Sends a real-time joint command. Positions default to **radians** — pass `degrees=True` to use degrees instead.
  </Accordion>
</AccordionGroup>

## Try a few more things

Once the quickstart runs, swap in these snippets to explore other capabilities:

<Tabs>
  <Tab title="Position the twin">
    ```python
    robot.edit_position(x=1.0, y=0.0, z=0.5)
    robot.edit_rotation(yaw=90)
    ```
  </Tab>
  <Tab title="Get a camera frame">
    ```python
    # Only camera twins have get_frame(); the SO-101 arm does not
    camera = cw.twin("cyberwave/standard-cam")
    path = camera.get_frame("path")       # saves a JPEG, returns the path (or None)
    frame = camera.get_frame("numpy")     # numpy BGR array (or None)
    ```
    Frames come from a paired camera in live mode, or from a running MuJoCo simulation. In the Playground, `get_frame()` raises `SimulationNotRunningError`.
  </Tab>
  <Tab title="Search the catalog">
    ```python
    for asset in cw.assets.search("unitree"):
        print(asset.registry_id, asset.name)
    ```
  </Tab>
  <Tab title="Drive a different robot">
    ```python
    dog = cw.twin("unitree/go2")
    dog.move_forward(0.5)   # speed in m/s for 1 s, then stop
    ```
  </Tab>
</Tabs>

## Go live on real hardware

The same code that drives the simulation drives a physical robot — you only change the affect mode:

```python
cw.affect("live")   # commands now go to the real robot
robot.joints.set("shoulder_pan", 45, degrees=True)
```

To connect real hardware, pair a device running the Cyberwave Edge Core (`sudo cyberwave pair` on Linux). See [Connecting to hardware](/overview/supported-hardware) for the full walkthrough. Without a paired device, live commands are sent but nothing moves.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication error / no API key found">
    Make sure `CYBERWAVE_API_KEY` is exported in the **same terminal session** where you run your script. Verify with `echo $CYBERWAVE_API_KEY`. If you opened a new terminal, re-export it or add it to your shell profile / a `.env` file.
  </Accordion>
  <Accordion title="400 workspace_required">
    Your token covers several workspaces. Set `CYBERWAVE_WORKSPACE_ID` to the workspace you want (the error lists them), or pass `Cyberwave(workspace_id=...)`.
  </Accordion>
  <Accordion title="Asset not found">
    Confirm the `vendor/model` identifier exists in the [catalog](https://cyberwave.com/catalog). You can also search programmatically with `cw.assets.search("so101")`.
  </Accordion>
  <Accordion title="Python version errors">
    The SDK requires Python 3.10+. Check with `python --version`. Consider using a virtual environment: `python -m venv .venv && source .venv/bin/activate`.
  </Accordion>
</AccordionGroup>

More errors, with exact messages and fixes: [Troubleshooting](/support/troubleshooting).
